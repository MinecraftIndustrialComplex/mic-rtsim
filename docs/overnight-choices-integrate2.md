## One interest area per player (R31, T17)

| # | Choice | Why |
|---|---|---|
| U2 | **The shared area is the world's own interest leg** (`PlayerState::interest`, saved with the world), booked by `World::observe_area` with the rule the dragons' and the ships' own areas followed: kept while the player stays within a quarter of the radius and it still covers the next window, else booked for two windows. Its radius is the widest module view (all are 160 blocks today). Modules see it through the new `rtsim_world::interest::Viewer` trait: `area_booked` (the ships book the voyages it could see), then the legs sharing its cells are looked up **once** and each crossing goes to the module that owns the traveller (`World::route_area`). Owner bits are a registry in that trait's docs: 63 players, 62 dragons, 61 ships, 60 reserved for herds, none for caravan rows. | Before, the world, the dragons and the ships each booked a leg per player, and a dragon's flight met three areas: three meetings, two found stale (measured in `a_flight_over_a_player_meets_one_area`: own areas (3 legs, 1 seen, 2 stale), shared (1, 1, 0)). The world already owned the leg index and the players, and its leg is saved with it. |
| U3 | **PLAYER positions go in once per hand-over** (`engine/shared.rs`): the latest per player is kept from the observations and applied at the simulate point, after the dragons and the ships ran to the hand-over's time. A player not reported for 200 game ticks leaves (phase 1's PLACEHOLDER); a session start clears every area. Areas are booked only while a module that sees players runs, so a phase 1 world alone keeps its cheap tail saves (S13). | The dragons applied each PLAYER as it was read, running themselves to the hand-over's time first; journaled records later in the same hand-over then met dragons already past them. Players' presence, like puppets, never outlives a session. |
| U6 | **Caravan rows' crossings are handed back unclaimed** (`route_area` returns them): the native phase 1 link materializes caravans by polling `World::visible` every 20 game ticks and needs no event, while `World::encounters` and `World::visible_to` read the shared area. **Herds** join by implementing `Viewer` (legs under bit 60), a `running` check and a `run_engine` step, and one line each in `shared::with_viewers` and `shared::run_to` (pointer in `engine/shared.rs`'s module docs). | No phase 1 behaviour changes (its GameTests and protocol tests are untouched); the herds crate is being written in parallel (`mic-rtsim-herds`). |
| U7 | **One clock for the modules in the phase 1 world**: `shared::run_to` runs the dragons and the ships in rounds, each to the earliest next event either has (a lower bound from their timing wheels), so neither meets a world the other ran past its time. Phase 1 inputs and every module record run both to their time first (`shared::catch_up`, which replaces `dragons::catch_up`). | Two event engines on one world: run one after the other, the second's events would see a world at the end of the step. Each round pops everything due up to its time and neither schedules the other's events, so the rounds' times rise and the loop ends. |
| U8 | **The modules' own areas stay** (`Dragons::observe_player`, `Ships::observe_player`, `World::set_player_pos`): the CLI scenarios and each crate's tests drive them as before, and their behaviour and event order are unchanged (the booking code was split into the pieces the viewer calls, in the same order). In shared mode a module keeps no area of its own (`PlayerView::interest` stays `None`), so its `player_left` never cancels the shared one; `Dragons::observe_home` feeds the home counter alone. | The brief: additive public APIs, every existing test green. Mixing both modes for one player is not supported (they would replan the same leg). |

## Module switches (C25)

| # | Choice | Why |
|---|---|---|
| U10 | **A switched-off module is frozen** (the dragons under `Module.ECOLOGY`, bit 4; the ships under `Module.SHIPS`, bit 6): it ignores its records (journaled ones are still admitted by `Replay` for their sequence and op id, then dropped and counted), runs nothing, decides and writes nothing (its queue is dropped: all its commands are per session), sees no player's area, and **keeps the page it had**: a save writes the bytes it last wrote or read, so the disk holds what it held, and a switch-off in the middle of a session writes the state of that moment once. **On again** (MODULES in a session, or a session start with the bit), its bodies of before are gone (its session reset) and it runs on from where it stopped, its missed events at once. | PLAN.md §5.4: "a module that is off registers no systems and takes no observations; its saved pages stay on disk untouched". The plugins report nothing with the module off (Z9), so what is ignored is only a straggler replayed from the journal. This departs from the industry link's W8, which still applies journaled records while off; Ben may want one rule for both. Before this, the dragons with ECOLOGY off still applied journaled records and wrote the commands those decided (a materialization could go out with the module off). |

## A lane's hazard in trade prices

| # | Choice | Why |
|---|---|---|
| U9 | **A hunted ships' lane is priced as an expected loss**: the allocation's margin for a lane direction with pirates (`Dir::predation`) falls by the raided share of the destination's bid (`rtsim-world` `flows::lane_loss`), since the destination pays only for what arrives. Roads are unchanged (phase 1's raided roads keep their rule, so no phase 1 test moves). `WorldConfig::price_lane_hazard`, default on, restores the old allocation. The test `raids_in_view_send_loot_to_the_haven_and_conserve_every_good` sets it off: at its 400 per mille hazard (60 per mille per unit of strength, capped) traders leave the lane at once and no merchant in view carries anything to loot, and that test is about raids in view. | The smallest change: one term in one margin. Conservation is untouched (only which edge gets the flow changes; checked after the run). Measured (`a_hunted_lane_is_priced_as_an_expected_loss`, coast seed 5, a 300 per mille hazard on the busiest lane at day 4): 1,394 thousandths a quantum allocated before the hazard; six days later 506 with the hazard ignored, 0 priced. |

## Not done

- **The kernel follow-up** (`overnight/kernel2`: paging, two save generations) had not merged
  into origin/main when this branch finished (origin/main was this branch's base, 4abe0f0), so
  the modules stay on the current `PageStore` (brief item 5).
- **No Java**: no ships plugin exists (P8), so nothing in Java sends ship records or encodes
  SHIP_COMMAND; the fake plugin in `crates/rtsim-jni/tests/common` (`ship_obs`, `ship_command`)
  is the reference. No GameTest was run (no Java changed).
- **A hold that fills while docked** reaches the body only at the next docking (U18): the body
  shows less than the engine holds until then, never more.
- **Navies are not in the native engine**: no record announces one (the crate's `add_navy` is
  called by the CLI and tests only).
- **Ports before their village** are dropped, not held (U13).
- **The clock's lower bounds** are slot starts on a wheel's upper levels, so a long catch-up with
  both modules running takes a round per occupied slot; not measured at scale.
- **Herds** are not wired (being written in parallel); the pointer is in `engine/shared.rs`.
- Review 3's open items and the ships crate's own "Incomplete" list are otherwise untouched.
