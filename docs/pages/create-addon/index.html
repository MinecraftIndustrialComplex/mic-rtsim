The Create addon is easy to package and not yet ready to ship

What releasing the shared native library and rtsim's factory sim as their own Create addon would involve. Checked against the repos, Modrinth's and CurseForge's rules and Create's release history on 21 October 2026.

It would be three mods in one download: mic_native (loads the Rust library), mic_rtsim (the engine, with only industry switched on) and mic_rtsim_create (the Create hooks). Both sites accept a jar with native code inside, and Sable, already in the MIC pack, ships its Rust physics that way. What stops a release is the product and the repos: the exact replay of Create machines is still on a branch, Create 6 package loops replay as making nothing, there is no Create-only build, and every repo it needs is private. UR-1 removes the save-format question: deleting and reinstalling only ever loses production owed to unloaded chunks.

Players would get factories that keep working with nobody near them

Create factories stop when their chunks unload, so servers either run chunk loaders or lose the output. rtsim learns each factory's inputs and outputs while it is loaded and keeps paying them out while it is unloaded: the items are in the chests when someone comes back. Create already moves trains through unloaded chunks; rtsim adds the station exchange there. On three public Create worlds rtsim's own work cost 0.2 to 0.5% of the server thread (about 0.1 to 0.25 ms a tick).

I found nothing on Modrinth that simulates unloaded Create factories. The nearest neighbour, Create: Meta Logistics (GPL-3.0, 41,017 downloads, updated yesterday), reads remote storage and chunk-loads a 3x3 area for 5 minutes when a train arrives. It loads chunks; rtsim avoids loading them.

Three things are different from how the question framed it

  • It is three mods, not one jar. NeoForge's jar-in-jar can nest them so players download one file, as Sable does.
  • There is no industry-only engine. rtsim-jni links all 12 Rust module crates, and the workspace has no Cargo features. The module switches (C25) are runtime config, and all nine default to on, so a plain install would also veto wandering traders (C8a) and run herds.
  • A fourth private repo comes along. The engine pulls in deeptime-format from Deep Time, through rtsim-space.

AGPL costs server owners nothing unless they change the code

Running it unmodified costs a server owner nothing. If they change the code and let players connect, they must offer those players the changed source.

A modpack that includes the jar has to say where the complete source is. That source includes everything linked into the engine, so deeptime-format has to be published or cut out.

UR-1 lets the description say: delete it any time

No save-format promise is needed. A format change, a reinstall or a failed load resets rtsim's state (SRV2), and it re-learns from the world. A reset loses production owed to unloaded chunks and what the sim had learned. It never loses a player's items or blocks, because rtsim never holds the only copy.

Uninstalling was tested on two public stress worlds. Both boot and run normally. NeoForge logs one warning for the missing mods and one skipped-attachment line per seeded chunk on the first load (73 and 46), then stops. rtsim's files stay behind, inert. The trader gamerule left off there is fixed by the trader veto (C8a). The one path not yet measured is a reinstall after playing without it (first safety row above).

Both sites take a jar with native code inside; neither asks for source

  • Modrinth. The Content Rules (13 August 2026) say nothing about native code. They require every dependency to be declared and the license and disclosures to be correct. Its malware scanner can send a file to manual review, which slows approval. An open request (modrinth/code#7631) asks for a native-code disclosure.
  • CurseForge. External download links are banned, so the natives must sit inside the jar, as mic_native already does. Files pass automated checks and manual review, and the malware processor can take days. Open-source credits are required. CurseForge modpacks can only include mods hosted there.

Support means strangers' packs, Create updates and native crashes

  • Other performance mods. It has only run inside the MIC pack (168 mods) with C2ME, Lithium, ModernFix, FerriteCore, ServerCore and Clumps. Lithium crashed the tick-order read on a stress world until 1ed1774 fixed it. Public packs mix differently, so expect a few such reports in the first weeks.
  • Create updates. One check and possibly one release every 2 to 3 months, and a real port at 6.1.
  • Native crashes. A crash inside the Rust engine does not give a Java stack trace, so each release's debug symbols need keeping.
  • Bug reports. They arrive on the public repo. An issue template asking for the mod list, the log and /rtsim district perf keeps them readable. With a mirror, pull requests need porting back to the private repo.

Four decisions are yours, recommendation first

1. What becomes public (REL-1 says nothing new does)

Recommended: once the list is done, publish a source mirror of only what ships (mic-native, plus mic-rtsim's engine crates, core and Create hooks), exported each release without history. Deep Time and the viewer stay private.

The private repos' history and docs describe your server and the rest of the pack. A mirror ships the code without them.

  • Open mic-rtsim and mic-native whole, with history: simpler, and the history goes public.
  • Stay private: no public release; MIC keeps copying the jars (REL-1 as it is).

2. The license

Recommended: keep AGPL-3.0-or-later for the engine, core and Create hooks, and MPL-2.0 for mic_native (A2, A7, A18).

  • GPL-3.0: no network clause, so a server could run a changed version without sharing it.
  • LGPL-3.0 or MPL-2.0: weaker; closed mods may build on it, and there is no network clause.

3. The name

Recommended: Create: Distant Factories. It says what players see, a far factory still working, without chunk jargon.

  • Create: Unloaded Factories (literal, for players who know chunks).
  • Create: Offline Factories (shorter, but reads as "no internet").

No Modrinth project uses any of the three names. The mod ids can stay mic_rtsim and mic_rtsim_create.

4. When

Recommended: an alpha on Modrinth and CurseForge on the same day, once the 14 items are done. Addon machine models (G4) follow in updates.

  • Sooner: once the 8 safety and packaging items are done, release the learned-rate replay from main as an early alpha, and add the exact replay later. Feedback comes sooner, but players' first impression is the weaker model.
  • Later: wait for G4, so packs full of Create addons get the exact replay too.

Choices I would make myself (all reversible)

  • One codebase: MIC runs the same jars, and its config turns the other modules on. The addon's defaults switch on industry only.
  • Cut deeptime-format with a Cargo feature rather than publish it.
  • Leave the viewer out of the first release.
  • Keep the natives inside the jar, and say so in the description, with links to the source and the build script.
