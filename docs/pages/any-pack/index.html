rtsim already runs non-Create factories, because it never models machines

How far rtsim's factory sim is from working on any pack, with any tech mods, from a few mods in single player up to a 500-mod SMP. From the generalization note on main (5578751); mod facts were checked against each mod's 1.21.1 source.

rtsim measures the stock at a factory's edge, learns the net rate of each good and replays those rates while the chunks are unloaded. Any block entity with a NeoForge item, fluid or energy capability counts, so a Mekanism, Immersive Engineering, Modern Industrialization or GregTech factory with no Create is grouped, learned and replayed today, with no plugin. What breaks on a non-Create pack is generic plumbing: four small fixes, each under about 500 lines. The real per-mod work is storage networks and wireless links such as AE2 and Refined Storage. The number of mods costs nothing per tick; the size of the world does.

What breaksTodayFix

Where rtsim cannot see something, the factory learns that nothing happens and stays frozen while unloaded, which is what vanilla does anyway. An AE2 base today is that case: its machines pull from and push into the ME network, no chest changes, so nothing is replayed. It is never worse than without rtsim.

Building now, without asking: G0 to G3

The district fix they waited on (DS-10: only machines start a district) is on main since 02c2096. Each is small and can be undone:

  • G1 and G2 fix MIC itself: the district seed fix, automatic adoption, the storage list, and screens that no longer wipe learning.
  • G0 is what the Create addon needs, and it puts industry tunables in the server config.
  • G3 is one tag file. The MIC pack has no Pipez, SFM or AE2, so it pays off only on other packs.

You chose "a by-product" (GA-1), so the slices after these are the ones that also serve MIC or the addon: G4, G6, G7, G8 and G10. The per-mod plugins (G5, G9) wait until a non-MIC release is on the table.

The TBSMP run finished: rtsim works on someone else's Create pack, and most size questions stay open

rtsim ran on TBSMP Season 2's own pack with all 11 dimensions, with no rtsim error or warning, at about 0.6 ms a tick. Four areas were adopted by command, not the whole world, so it answers less about size than hoped. The full result is on the test worlds page.

  1. Version spread: not tested. The test moved the world to Create 6.0.10, rtsim's pin, rather than run rtsim on 6.0.6. Three small fixes covered the Create addons MIC lacks.
  2. Detection at scale: 7 detection runs took 237 ms in all over the four areas. A whole-world rescan was not measured. Spreading the rescan over several ticks, part of G6, is being built anyway (ST3).
  3. District count and memory: the four areas made 6 districts holding 1,142 inventories. Live heap after GC rose 17 MB (2,474 to 2,491 MB), and rtsim's save directory was 138 kB.
  4. Goods growth: not reported by the run.

It could not test non-Create factories, because TBSMP is a Create pack. That needs a Mekanism or AE2 world; the ATM10 Season 2 sample is the candidate.

You took the recommendation on all four

Answered on 21 October 2026 (DECISIONS.md GA-1 to GA-4).

1. Is "any pack" a goal?

A by-product (GA-1). Build only the slices that also serve MIC or the Create addon (G0, G1, G2, G4, G6, G7, G8, G10), and leave the per-mod plugins for AE2, RS2, Mekanism and IE until a non-MIC release is on the table.

2. How storage networks and wireless links are modelled

A shared store in Rust with ports (GA-2, slice G4). Districts stay small, and a district trades with the network's store.

3. The machine model for non-Create mods

Recipe-constrained learning first (GA-3, slice G7), recipe-based exact replay later (G11). No per-mod Java until a pack needs exactness.

4. Release shape for a non-MIC pack

Nothing public for a non-MIC pack until you say so (GA-4). G0 and the in-tree parts of G12 are built so a release is a switch, not a project.
