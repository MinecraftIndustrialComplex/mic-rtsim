# Overnight choices: the native link (2026-10-20)

Reversible choices made while building `crates/rtsim-jni` (the cdylib that joins the bridge, the
native host `mic_native` and the kernel) and the bridge's `NativeEngine`, one line each with the
reason. None is in DECISIONS.md; each can be undone or put to Ben. Numbers marked PLACEHOLDER are
not measured.

## Dependencies and packaging

| # | Choice | Reason |
|---|---|---|
| J1 | `mic-native-rt` (and, for rtsim-jni's tests, `mic-native-host`) is a **git** dependency on the private repo `MinecraftIndustrialComplex/mic-native`, pinned to commit `63add99` in the workspace `Cargo.toml`; `.cargo/config.toml` sets `net.git-fetch-with-cli` so cargo fetches over SSH with the git command. | Other sessions edit the mic-native checkout; a path dependency would build whatever its working tree holds that minute. A pin is reproducible and bumps deliberately. A `[patch]` to a local checkout serves joint work on both repos. |
| J2 | The GameTest runtime and `compileOnly` take the **built mic_native jar** from the sibling checkout (`mods/mic-native/neoforge/build/libs/mic_native-1.21.1-0.1.0.jar`; `-PmicNativeDir`, `-PmicNativeJar` override); `buildMicNative` runs mic-native's own Gradle build only when the jar is missing. The jar used tonight reports host `0.1.0+90fbcc7` (ABI 1.0, the same ABI as the pinned runtime crate). | mic-native is not on a maven. Building it inside this build every time would rebuild its Rust natives on every run; the MIC repos already use `localRuntime(files(...))` for sibling jars (mic-climate). |
| J3 | `mic_rtsim` declares `mic_native` as a **required** dependency (`[0.1.0,)`, ordering AFTER, side BOTH). The README reads D4 as allowing it: mic_native is MIC's own host, not a pack content mod. | A8 and PLAN.md §2: no plugin runs without the host, and there is no fallback. |
| J4 | The plugin is loaded when the first `NativeEngine` opens (server start), through `MicNative.loadPlugin("mic_rtsim", "rtsim_jni")` and then `System.load` of the same path from `NativeEngine`, so the natives bind to mic_rtsim's class loader. Every mic_native reference sits in a nested class (`MicNativeLink`), so `NativeEngine` links without mic_native and a missing host is a clear error. | The host starts in mic_native's mod constructor; loading at server start needs no mod-order guarantee and keeps a broken native from stopping a world that runs the stub. |
| J5 | `tools/natives/build-natives.sh`, adapted from mic-native's (MPL-2.0, provenance in its header), builds rtsim-jni for the eight platforms plus x86-64-v3 on the four x86-64 ones (12 libraries, no CPU probe: a plugin takes the host's choice). It runs in mic-native's dev shell (zig 0.13, cargo-zigbuild, cargo-xwin, the same Rust 1.98.1), writes `target/natives-dist-jni/`, and `./gradlew build -Prelease` packs it. Added for it: the workspace `ship` profile (fat LTO, one codegen unit, no debug info), the musl and Intel-macOS target flags in `.cargo/config.toml`, an `@rpath` install name (`crates/rtsim-jni/build.rs`) and a CPU-level literal the script checks (`lib.rs` `CPU_LEVEL`). | mic-native's builders and checks (glibc 2.17 floor, musl without glibc, PE machine, macOS 11.7.1 and system dylibs only, BMI instructions in the v3 build) already pass for the host; one script per library keeps them identical. The dev Gradle build packs only this machine's baseline build. |
| J6 | The natives manifest's `version` is the mod version (`0.1.0`), its `format_version` the mic_native C ABI it was built for (`mic_native_abi = 1.0` in `neoforge/gradle.properties`). | mic_native's `PluginLoader` checks the ABI major version and extracts under `<version>-<sha12>/`. |

## The engine side of the boundary

| # | Choice | Reason |
|---|---|---|
| J7 | Steps run on mic_native's **background pool** (`rt::spawn`); a step publishes its command buffer as its very last act on the buffers, and the next step takes the state lock under `rt::blocking`. | Java may submit step h + 1 the moment it sees step h's `published`, while step h is still in its last lines; the protocol test caught a `try_lock` failing there. `rt::blocking` lends the pool thread's slot while it waits (microseconds). |
| J8 | A step that panics marks the engine failed; from then on every step consumes its observations and publishes an empty command buffer. Protocol errors are logged through the host and kept for tests. | The bridge never waits, so a step that never publishes would stall it silently forever. |
| J9 | The engine's pages are two pages of the kernel's `PageStore` in `<world>/rtsim/`: key 1:0 holds `Replay` and the `Outbox`, key 1:1 the world. The snapshot is encoded on the step thread at the step boundary; compression and the fsync'd commit run on the **IO lane**. `ackedObsSeq` is the observation sequence of the last commit that finished. The stub's `stub-pages.bin` may sit in the same folder; the store only touches its own file names. | PLAN.md §4.9: snapshot at a step boundary, write off-thread, acknowledge only what is on disk. Two pages are enough for the minimal world; real modules bring their own tables. |
| J10 | `requestSave(through)` takes the snapshot right before the first journaled record past `through`, or at the end of a step once everything through it is applied; a later request replaces an earlier one. | docs/boundary.md §1.3 and B52: the pages never get ahead of the world save. The same rule as the stub. |
| J11 | Only **TRANSFER_TO_CONTAINER** goes through the kernel's `Outbox` (saved with the pages, resent first after a restart with its original sequence and op id). Spawn, despawn and steer take a sequence from the same counter but are never kept or resent. | Puppets never outlive a session: an old SPAWN_GROUP replayed into a new session would be wrong, and the engine decides again. |
| J12 | **DICT commands carry `cmdSeq` 0.** | Java never skips a DICT but does record its sequence as applied; a DICT written before a resent transfer would otherwise get a sequence above the transfer's original one, and Java would then skip the transfer as stale. docs/boundary.md §2.4 now says so. |
| J13 | Engine op ids skip 0. | The kernel's `OpIds` count from 0, and 0 reads as "no op id" on the wire and in orders. |
| J14 | A `Replay` gap (a journal trimmed past the pages) is logged and counted, then `Replay::skip_to` moves on. An empty journal (`journalFirstObsSeq` 0) is read as `worldNextObsSeq` for `reconcile`, as the kernel documents. | Nothing can bring lost observations back; refusing everything after them would stop the sim for good. |
| J15 | A record is a replay (and a replayed MATERIALIZED never embodies) when its sequence is below the session's first, `max(worldNextObsSeq, pagesObsSeq + 1)`. | The same rule Java's `BoundarySession` uses to start the session's sequences. |
| J16 | TAKEN, DIED and COMMAND_RESULT (applied or duplicate) go through `Replay::admit` with their op ids; once a durable world save lets `Replay` forget an op (WORLD_SAVED), the world refuses a repeat by state (a member already gone, an op already done). | docs/boundary.md "Idempotent events". |
| J17 | The minimal world's ledger is two-sided (a TRANSFER credits `to` and debits `from`); the stub only credited `to`. | Transfers conserve (SCALE.md §9); the tests read `to` only, so both pass. |
| J18 | `close()` waits up to 5 s for a step in flight, then saves through the IO lane and waits for it (the server thread waiting on IO is not an inversion). `close(save = false)` is the tests' crash: queued saves are dropped (a `dead` flag) and the IO lane is flushed, so no save lands after the same folder is reopened. | B31's shutdown order puts captures in the journal; the pages then hold everything handed over, never more. |
| J19 | Command buffers default to 256 KiB of records (PLACEHOLDER, the stub's). | PLAN.md §4.5 sizes them from puppet caps and quotas, which are not measured yet (P24). |
| J20 | JNI handles are a boxed `Arc<Engine>`; each step and save job holds its own `Arc`, so the buffers Java sees live until a running step ends even after `nClose`. | Java must not touch a handle after close (`NativeEngine` guards it); the engine's memory must not vanish under a step. |

## Tests and the test surface

| # | Choice | Reason |
|---|---|---|
| J21 | Both engines implement one test surface, `ScriptedEngine` (spawn, despawn, steer and transfer orders; the received log; ledger and op inspection; `awaitIdle`; `crashAndReopen`), and every GameTest uses it. The native engine takes orders through one JNI call, `nOrder(byte[])` (encoding in `orders.rs` and `NativeCodec`); one call is one unit (all in one command buffer, or all wait). | The existing GameTests run unchanged against either engine. Orders stand in for the sim's decisions; the engine writes them with its own sequences, dictionary, outbox and bookkeeping. |
| J22 | The received log and an inspection snapshot exist only in TEST mode (an `nOpen` flag the GameTest run sets): the log is a channel Java drains, the snapshot a `SnapshotCell` published after each step. | No lock a game thread takes; nothing costs anything in play. |
| J23 | The server's engine is a config switch, `engine.implementation` = `native` (default) or `stub`; `-Dmic_rtsim.engine` overrides it in GameTest runs only (B28's convention). A native engine that cannot open starts no session (logged; `/rtsim perf` gives the reason): no fallback to the stub. | The task's "a config switch, the stub kept for tests", and A8. |
| J24 | GameTest agent ids start at a random base per server run. | The GameTest world is reused (B37): a run starts by replaying the last run's shutdown captures, and a world first run on the stub replays its whole journal into empty native pages. Fixed ids made those replays look like this run's records. |
| J25 | rtsim-jni's protocol test runs the real host in process (`mic_native_host::start`, `register_in_process`) with a Rust copy of `Handover` and `BoundarySession` as the fake Java side. | The steps run on the real background pool and the saves on the real IO lane, which is where the races are. |
| J26 | The hand-over bench is a GameTest gated by `-PrtsimBench`: burst and 50 ms cadence, three payloads, native and stub. Results in `bench/results/handover.md`. | It measures the real JNI path and the real pool inside the real server; a JMH harness would need its own host setup. |
| J27 | The order and received-log encodings live in a package-private `NativeCodec` with pure-Java unit tests; `StubEngine` gained `closeWithoutSaving()` and an idempotent `close()`; `engine.implementation` uses `defineInList` with `Arrays.asList` (NeoForge's `contains(null)` check threw on `List.of`). `freshEngine()` folders under `run-gametest/mic_rtsim-test/` are never cleaned up. | Small fixes found on the way (the Java half). |
