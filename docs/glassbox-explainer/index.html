mic-rtsim / industry / glass box (C28)

The glass box: distant Create factories, compiled

When a factory's chunks unload, mic-rtsim keeps running a compiled copy of it. Java reads the real Create graph once per edit; the Rust engine solves it the way Create behaves, jumps from breakpoint to breakpoint, and writes the result back into the chunks exactly once when they load. Measurement checks the model, and the replay never runs ahead of what was measured.

Status: designed and approved on 2026-10-20 (C28, G-B1 to G-B19). Nothing is built yet: phase G1, a read-only compile checked against the black box, starts after the industry rework merges. The numbers below were measured on code that exists today and that the glass box keeps (C29).

§1 / G-B3, G-B5, G-B19, I8

One compile per edit, then the engine runs alone

Java reads the graph on the server thread, a slice per tick, when a district is found, a player edits it, or its settings hash changes. Records cross the boundary with a count, and one lost record throws the compile away. The engine compiles, solves, waits for one agreeing checksum window, then replays until a player comes near and the reconcile lands exactly once.

§2 / C28, G-B5, G-B12

The compiled model: Create's own numbers on every node

Each machine's cycle comes from Create's code at its network's speed, and each kinetic network is one stress budget. Stress does not depend on work, so an idle mixer loads its network exactly as a busy one does, and an overstressed network stops every member at once. Batch size matters too: the feeder sets it.

§3 / G-B1, G-B15

The solve: Create's back-pressure, with the LP only as a ceiling

Create plans nothing. Every mover pushes as soon as the next thing has room, and every machine runs while it has inputs, power, heat and output space. The steady state is the greatest fixed point of that rule: start every edge at capacity and lower rates until nothing changes. An LP that maximizes output would route around a forced split and claim more than Create makes, so it serves only as the ceiling U.

§4 / G-B2, SCALE.md §0

Replay: straight lines between breakpoints

Within a regime every rate is constant, so every store is a straight line. The engine solves once per regime and jumps to the next breakpoint: an input empties, an output fills, fuel runs out, a train arrives. Catch-up costs O(breakpoints + events), never anything per tick of time away.

§5 / G-B8, G-B9

Switches and timetables: counted, not stepped

A threshold switch makes Create cycle between its two levels. Decided (G-B8): the sim runs those on and off cycles, and when a cycle is strictly periodic it counts them in closed form, as it does a clocked requester or a ship: b × (floor((t − φ) / P) + 1). A million days cost one evaluation.

§6 / G-B4, G-B14, I18

The checksum: measurement keeps the model honest

While loaded, the sampler fits a slope per good each window and the model predicts the same window. A good fails when they differ by more than z·σ + q. A compiled district may replay only after one agreeing window (G-B4). On a disagreement the policy is cut, search, demote, report (G-B14).

§7 / I7, G-B6

Half loaded: Minecraft runs one side, the engine the other

Nodes in ticking chunks are live: Create runs them and the sampler reads their stores. The rest keep being simulated (I7). Decided (G-B6): flow across the loaded/unloaded edge is modelled, not zero. When the cut closes, all loaded or all unloaded, the district solves as one again.

§8 / C30, C32, G-B7, G-B9

Ben's server: a sheep farm that flies

A player on Ben's server built a farm of about 2,000 sheep on a Create airship, served only by a second airship ferrying its cargo. C32 makes that a supported case. The farm is a factory compiled in the ship's own frame, following it as it moves and freezes. The ferry is a periodic edge with both ends moving, and either ship materializes wherever a player can see it (G-B7).

§9 / where it sits

Where the glass box sits in mic-rtsim

The glass box is one part of the industry module, beside caravans and markets, dragons, herds, ships, conflict and the world model, all on one kernel. The server thread only hands records over: 11 to 20 µs per tick at p50, measured with phase 1 running on 64 villages and four players.
