# Overnight choices: the industry engine behind the native link (2026-10-20)

**Overnight agent 12.** Reversible choices made while wiring `crates/rtsim-industry` into
`crates/rtsim-jni` (the cdylib behind the bridge's `NativeEngine`), one line each with the reason.
None is in DECISIONS.md, INDUSTRY.md or PLAN.md; each can be undone or put to Ben. The engine's own
choices are F1 to F37 (`docs/overnight-choices-industry.md`), the native link's J1 to J34
(`docs/overnight-choices-jni.md`), the Java side's H# (`docs/overnight-choices-industrymc.md`, on
its branch until it merges). Numbers are measured on this laptop (AMD Ryzen AI MAX PRO 390,
release build) unless marked PLACEHOLDER.

## Where it lives

| # | Choice | Reason |
|---|---|---|
| W1 | Everything industry is `crates/rtsim-jni/src/engine/industry.rs`, a child module of `engine.rs`. The step calls it at five points and nowhere else: **observe** (SESSION_START, the non-journaled arm for DICT, MODULES and the latest-wins kinds, the `Replay::Apply` arm of journaled records it claims, `op_of`), **simulate** (the "2. Simulate" point of `step_inner`), **write** (resends merged with the core's, then its queue after the order units), **save** (its pages in the same `SaveBatch`) and **orders** (a threat). | A phase 1 integration will rework `engine.rs`; one module behind single-line hooks keeps the two apart. A child module reads the step's `State` (sequences, the core's dimension dictionary) without widening its API. |
| W2 | The industry engine runs in **apply** mode (phase I-B). Read-only (F25, phase I-A: ledger lines only) is an `nOpen` flag, `FLAG_INDUSTRY_READ_ONLY = 4` (`Config::industry_read_only`); the Java side does not pass it yet. | The Java side applies every industry command (H15 to H20) and its GameTests exercise the apply path; I26 orders what is built, and both phases are built. **For Ben:** which phase a played world runs is a product call; the flag makes it one line in `NativeEngine`. |
| W3 | **Industry op ids are derived from the command's identity**: namespace 0x49 in bits 56 to 62 (F4, unchanged) over the low 56 bits of FNV-1a 64 (the kernel's `rng::fnv1a64`) with SplitMix64's finalizer, over the world seed, the engine's tick when the change was decided, an ordinal and the command with its op cleared (kind, target, epoch, every delta). Two identical commands in one tick take ordinals 0 and 1; a hash that meets another id of the same tick takes the next ordinal. `IndustryOps` no longer counts (`rtsim-industry/src/cmd.rs`). | docs/boundary.md §2.2 and J13: a counter restored from the pages hands out again, after a crash, the ids it gave since the last save, to different commands that the bridge (its journal's applied set, or a chunk carrying an IND_RECONCILE_RESULT, H16) answers DUPLICATE and drops. The game time rolls back with the world, so the tick alone does not separate a new decision from an old one: the command's content does. Re-deriving the same decision gives the same id (shown by `a_reconcile_is_rederived_and_applied_once_after_a_crash_before_the_load`). |
| W4 | **Kept commands.** IND_CARRIAGE_DELTA, IND_CHANNEL_DELTA, IND_DEPOSIT_DELTA and IND_WRITE_PACKAGE stay in the link's outbox from the moment they are written until Java's answer is admitted through `Replay` (IND_CARRIAGE_RESULT, or COMMAND_RESULT applied, duplicate or failed). `start` drops those at or below the world save's `lastAppliedCmdSeq`; the rest are written again first, with their original sequences and op ids, merged with the core's resent transfers in sequence order. IND_CHUNK_RECONCILE is not kept (the industry engine keeps every pending delta and resends it at the chunk's next IND_CHUNK_LOADED, F27), nor IND_LEDGER (a reply). Every industry command takes its sequence from the core outbox's counter when it is written. | J11's rule for transfers: a snapshot taken at observation N then holds exactly the commands the world save at N lacks. Java skips any command at or below the last one it applied, so the two resend queues must interleave by sequence. The industry engine forgets a carriage, channel, deposit or package command once it is out (only its exchange record waits for a result), so without the outbox a crash between the engine's save and Java's would lose it. |
| W5 | A new industry engine draws a **random world seed**, then keeps it in its pages (`Config::industry_seed` fixes it, for tests). | Minecraft's seed does not cross the boundary; the seed only has to be stable within one world (draws, op ids). |
| W6 | **Pages.** The industry engine's own tables (0x4900 globals, 0x4901 per district, 0x4902 per replay cluster; F36) go in the same commit as the core's 1:0 and 1:1, every page at every save (F36: no dirty tracking yet). Pages the store holds in those tables that a snapshot no longer has (a district removed, a cluster merged or dissolved) are deleted in the same commit, computed from the store's own keys on the IO lane. The link's queue and outbox are page **1:0x49** (rtsim-jni's table, J9), magic `RTJI`, version 1. | A restore takes every page of the tables, so a stale cluster page would come back as a ghost cluster. Asking the store at commit time is exact even after a failed commit. Id 0x49 in table 1 keeps clear of the core's 1:0 and 1:1 and of whatever the core adds next. |
| W7 | **Dictionaries.** The engine's GOOD (0x10), NAME (0x11) and BLOCK_STATE (0x12) ids are Java's own (F2): before its first use in a session the link writes a DICT command with Java's id and name (GOOD names fall back to the engine's paged goods; a NAME or BLOCK_STATE Java never named goes without, and Java skips what uses it, as the protocol says for an unknown id). Dimensions are translated: Java's id to its name to the core's engine dimension id (`State::dict_id`), patched into IND_CHUNK_RECONCILE at 36 and IND_DEPOSIT_DELTA at 24. Java's DICT GOOD entries define the engine's goods (`GoodInfo::parse`). | The Java side reads every command id through the engine's dictionary (`Industry.engineName`, `engineLevel`). The core allocates dimension ids per session for its own commands, so industry commands share them; the mirrored kinds must never be allocated by the core's counters. |
| W8 | **The module switch** (C25; `Module.INDUSTRY`, bit 7 of MODULES and SESSION_START): off, latest-wins industry records are dropped, the engine neither advances nor writes, its queue waits, and its resends go back to the queue (they take new sequences when it is on again; Java skips by op id what it already applied). Journaled industry records are still applied, and the pages still saved. | "A module that is off registers no systems and takes no observations; its saved pages stay on disk untouched" (RtsimConfig). Journaled records say what happened in the world; dropping them would lose them for good once acknowledged. |
| W9 | **Game-time order.** A hand-over holds its latest-wins records before its journaled ones (the bridge copies the journal at the hand-over), while within a tick Java journals loads, ports and results before it samples stock. The link holds latest-wins industry records and hands them to the engine in game-time order with the journaled ones, journaled first on a tie; the rest at the simulate point. | Found by the iron line through the native engine: a sweep taken in a district's load tick reached the engine before its IND_LOAD_STATE, so the reconcile's removal met a stock it had just been told and left 2 coal unaccounted (conservation failed). IND_WATCHED sent in a load tick was dropped for the same reason. With W9 the native run is the in-process run decision for decision. A latest-wins record held when a mid-hand-over save is taken is not in that snapshot (latest-wins records may be lost anyway). |
| W10 | **Failed answers.** COMMAND_RESULT failed takes a kept command out of the outbox. A failed IND_CARRIAGE_DELTA moved nothing, so the engine hears an IND_CARRIAGE_RESULT with nothing applied (its stock correction). A failed IND_CHANNEL_DELTA, IND_DEPOSIT_DELTA or IND_WRITE_PACKAGE is logged and counted (`IndustryStats::results_failed`); the engine keeps its books as if it had been applied. A failed IND_CHUNK_RECONCILE stays pending in the engine and goes again at the chunk's next load. | rtsim-industry has no correction for the three level-SavedData commands (its own still-open list: IND_CHANNEL_DELTA and IND_WRITE_PACKAGE have no result). The Java side answers all three FAILED today (no Ender Transmission, Diesel or postbox-buffer plugin yet). **For Ben / the next engine round:** a failed one should give its goods back to the replay. |
| W11 | **At most once.** IND_PORT and IND_PACKAGE go through `Replay::admit` with Java's op id (at 48; 0 none), IND_RECONCILE_RESULT and IND_CARRIAGE_RESULT with the engine's (at 24): a result Java journals again from a chunk (H16) is skipped by op id while `Replay` remembers it, by state after (the engine's pending sets). The COMMAND_RESULT applied that follows a result under the same op id is then a duplicate op and is not dispatched. Industry COMMAND_RESULTs never reach the minimal world. | docs/boundary.md "Idempotent events". The minimal world's `done_ops` keeps every op id it hears for good; every industry command would grow it. |
| W12 | **Threats** from other systems reach the engine through an order, `Order::IndustryThreat` (opcode 8: id, source, class, count, strength, target district or train, game time), applied at the start of the next step, in any mode. | Orders stand in for the sim's decisions (J21): the dragons, conflict and kaiju modules will hand their attacks over the same way, or call `industry::threat` once they run in this step. |
| W13 | **Simulate.** At "2. Simulate" the engine advances to the hand-over's game time (`wordB`), its commands join the link's queue, and the queue is written after the core's order units while it fits (`MORE` otherwise). A command that can never fit, or names a dimension Java never named, is dropped with an error (J32). | The industry engine fires breakpoints by time; one advance per step keeps its cost O(breakpoints), not O(ticks). |
| W14 | **The test harness.** The fake Java side moved from `tests/protocol.rs` to `tests/common/mod.rs` (unchanged in substance) and plays the industry module with rtsim-industry's fake world in a new remote mode (F24 scaffolding): observations out, commands in through `deliver`, the bridge's own COMMAND_RESULTs, ledger lines kept, world saves and chunks saved ahead for crashes, `move_to_dim`, `iron_line_world`. World and engine run in lockstep: one hand-over a tick, its commands back before the next tick, so every run is deterministic. | "Use rtsim-industry's fake.rs as the Java model": it already applies reconciles the way §4.1 says (held until loaded, removals first, the epoch in the same tick). |
| W15 | **The stale-tick race** (INDUSTRY.md §19 risk 3; the industry choices' finding 2) has no policy here: Ben's call. The Java side's IND_APPROACH (0x0046, H23) was not on main when this branch merged; until it is in `wire.rs`, the engine counts it as an unknown industry kind and skips it. | The brief: wire an approach signal through as data only, if merged. |

  242,000 ticks, 9,654 observations, 122 industry commands (116 carriage deltas), 14 attacks, five

## Findings for Ben

1. **Within a hand-over, latest-wins records come before journaled ones** (W9). The link now merges
   them back by game time. The industry crate itself still takes records in the order given, so
   anything else that feeds it (a future in-process caller) must do the same.
2. **Op ids are now identity-derived** (W3), a change to `rtsim-industry`. The Java side needs no
   change: it treats op ids as opaque.
3. **Failed level-SavedData commands are not corrected** (W10): the engine's books assume they were
   applied. Harmless while the Java side has no plugin for them and the iron line has no channels,
   Diesel deposits or postbox mail; it needs a correction before those plugins exist.
